# claude-mods

Mods for [Claude Code](https://code.claude.com/docs/en/plugins/mods/overview), published as one plugin marketplace.

| Mod | What it does |
| --- | --- |
| [model-keys](mods/model-keys) | Pick model and effort with `ctrl+alt+arrows` or a click, plus a context usage bar and breakdown pane |
| [prompt-sharpen](mods/prompt-sharpen) | Rewrites each prompt you send to be more explicit before Claude reads it |

Both mods are also ported to [pi](https://pi.dev) and [opencode](https://opencode.ai); see [pi and opencode](#pi-and-opencode).

## Install

At the prompt of a Claude Code terminal session:

```
/plugin install model-keys --marketplace kygura/claude-mods
```

Answer `y` to add the marketplace, then pick a scope (user scope is first; press Enter).

From a shell:

```sh
claude plugin install model-keys --marketplace kygura/claude-mods
```

In the desktop app, where `/plugin` does not run: click **+** next to the prompt box, then **Plugins**, **Add marketplace** with `kygura/claude-mods`, then **Add plugin**.

### Install script (adds keybindings too)

Some mods need key bindings in `~/.claude/keybindings.json`. The script installs the mods and merges those bindings without overwriting any key you already bound:

```sh
git clone https://github.com/kygura/claude-mods && cd claude-mods
./install.sh               # every mod
./install.sh model-keys    # just one
```

Then run `/reload-plugins` in open sessions.

### pi and opencode

```sh
./install.sh --pi                        # every pi port, registered with `pi install <path>`
./install.sh --opencode                  # symlinks plugins into ~/.config/opencode/plugins, merges tui.json keybinds
./install.sh --pi prompt-sharpen         # just one
```

The ports import shared code from `mods/`, so keep the clone where it is. `--pi` needs `pi` on `PATH`; `--opencode` never replaces a file or a symlink it did not create.

**prompt-sharpen**

- pi ([`ports/pi/prompt-sharpen.ts`](ports/pi/prompt-sharpen.ts)): the rewrite uses the first available model whose id contains `haiku`, else the current model. The original wording reaches the model as a hidden custom message. Prompts starting with `/` (templates, skills) and messages typed while a run streams (steering, follow-ups) are not rewritten. `/sharpen` state: `~/.pi/agent/prompt-sharpen.json`.
- opencode ([`ports/opencode/prompt-sharpen.ts`](ports/opencode/prompt-sharpen.ts)): the rewrite runs in a throwaway child session on `small_model` (else the current model), with tools disabled and a system prompt of just the rewrite rules. The original wording is a synthetic part: the model sees it, the UI does not. Command prompts and subagent sessions are not rewritten. `/sharpen` is registered by the plugin; commands always reach the model in opencode, so toggling costs one short reply. State: `~/.config/opencode/prompt-sharpen.json`.
- Both: 10s limit, and any failure sends your original prompt.

**model-keys**

- pi ([`ports/pi/model-keys.ts`](ports/pi/model-keys.ts)): `ctrl+alt+↑/↓` step through your scoped models (`--models` / `enabledModels`), or every model with credentials when none are scoped. `ctrl+alt+←/→` step through the thinking levels the model supports. `/model-keys reset` returns to the model and level the session started with. A line above the editor shows the model, the level and the context fill bar. No reply stamp (pi's footer already shows the real model) and no breakdown pane (pi exposes only total context usage).
- opencode: no code. opencode already cycles models and variants and shows context usage, so the port is the keybinds in [`ports/opencode/model-keys.tui.json`](ports/opencode/model-keys.tui.json), merged into `~/.config/opencode/tui.json`: `ctrl+alt+↑/↓` cycle favorite models (mark favorites with `ctrl+f` in the model list), `ctrl+alt+→` cycles variants (effort), `ctrl+alt+←` opens the variant list (opencode has no reverse variant cycle). Actions you already bound are kept.

## Layout

```
.claude-plugin/marketplace.json   generated by scripts/build_marketplace.py
mods/<name>/                      one mod per folder (plugin.json, hooks/, optional keybindings.json)
ports/pi/<name>.ts                pi extension ports
ports/opencode/<name>.*           opencode plugin (.ts) or tui.json keybinds (.tui.json)
install.sh                        install mods + merge keybindings (--pi / --opencode for the ports)
sync.sh [-m msg] [folders]        import mods from dev folders, validate, commit, push
```

## Adding or updating a mod

```sh
./sync.sh ~/path/to/my-mod     # copies it into mods/<name>/, rebuilds the marketplace, pushes
./sync.sh                      # just rebuild and push what's in mods/
./sync.sh -m "feat(model-keys): add context pane" ~/path/to/my-mod   # custom commit message
```

`sync.sh` runs `claude plugin validate` on every mod and, when [gitleaks](https://github.com/gitleaks/gitleaks) is installed, scans the staged files for secrets before committing.
